## 提醒引擎 {#alert-engine}

一条提醒就是一组条件。每当某个材料和交易所有变化到达，PRUNplanner 会拿这个材料、交易所的新数值和之前的值，逐一检查每条启用的提醒。条件全部满足时，提醒就往推送里加一行。

条件里的字段取的是这条到达的变化里的新值，不是总览里的值。条件里的字段取的是这条到达的变化里的新值，不是总览里的值。如果这条变化里没有该字段，比如没带价格，那么作用在 **价格** 上的条件就不会命中。

PRUNplanner 把提醒存在这个浏览器里，只属于你的账号：「提醒目前只存储在这台设备上，不会同步到你的账号。」换一个浏览器或设备打开，就没有这些提醒。换一个浏览器或设备打开，就没有这些提醒。

### 设置条件 {#setup}

一个条件由三部分组成：字段、运算符和目标值。例如 **价格** 大于 **值** 100。例如 **价格** 大于 **值** 100。

#### 字段 {#fields}

| 字段                          | 含义                  |
| --------------------------- | ------------------- |
| **代号**、**交易所代码**            | 材料代号、交易所代码（文本）      |
| **价格**、**买价**、**卖价**        | 与总览里一样的价格、买价和卖价     |
| **价格变化**、**买价变化**、**卖价变化**  | 新值 − 之前的值           |
| **价格变化（百分比）**               | 价格变化 ÷ 之前的价格 × 100  |
| **需求**、**供给**               | 变化里报告的需求和供给         |
| **成交量**、**总量**              | 变化里报告的成交数据          |
| **买量**、**卖量**               | 所有未成交买单或卖单的单位数      |
| **买量变化（绝对值）**、**卖量变化（绝对值）** | 这个量变了多少，不带正负号       |
| **买入 VWAP**、**卖出 VWAP**     | 未成交买单或卖单按单位数加权的平均价格 |
| **最优买价**、**最优卖价**           | 订单簿里最高的买单、最低的卖单     |
| **价差**、**价差（百分比）**          | 卖价 − 买价，以及它占卖价的百分比  |

**价格变化**、**买价变化**、**卖价变化** 和 **价格变化（百分比）** 都需要有个之前的值，所以某个材料和交易所的第一条变化里它们是空的。那两个量的变化字段这时显示 0。那两个量的变化字段这时显示 0。

例如，之前的价格是 200 ȼ、新价格是 210 ȼ 时，**价格变化** 是 210 − 200 = 10，**价格变化（百分比）** 是 10 ÷ 200 × 100 = 5。

#### 比较方式 {#comparisons}

数值字段提供这些运算符：

- GT：大于
- LT：小于
- EQ：等于
- NEQ：不等于

**代号** 和 **交易所代码** 只有 MATCHES，表示相等，不区分大小写。它们的目标值永远是固定文本（显示为 **文本**）。它们的目标值永远是固定文本（显示为 **文本**）。

#### 比较目标 {#comparison-targets}

| 目标       | 把字段与什么比较                                  | 适合用来               |
| -------- | ----------------------------------------- | ------------------ |
| **值**    | 你自己填的固定数字（或文本）                            | 价格下限和上限，针对某种材料或交易所 |
| **上次值**  | 该材料、交易所这个字段上一次的值（**上一次数据点**）              | 任何变化，尤其是突然的跳动      |
| **偏移 %** | 上一次的值 × (1 + 偏移 ÷ 100) | 一定幅度的变动            |

**上次值** 和 **偏移 %** 在某个材料、交易所的第一条变化上永远不会触发，因为还没有可比较的值。

例如 **价格** 大于 **偏移 %** 2，会在价格比上次上涨超过 2 % 时触发。**价格** 小于 **偏移 %** −2，会在下跌超过 2 % 时触发。上次价格是 100 ȼ 时，第一个例子的目标是 100 × (1 + 2 ÷ 100) = 102 ȼ，所以新价格 102.50 ȼ 会触发，101.90 ȼ 不会。

#### 逻辑运算符 {#logical-operators}

条件放在一个组里，**匹配方式** 决定组内条件怎么组合：

- AND：组里每个条件都要满足。
- OR：满足一个条件就够了。

组里还可以放组（**组**）。这样就能写出类似（**代号** MATCHES RAT 且（**价格变化（百分比）** 大于 2 或 **价格变化（百分比）** 小于 −2））的条件。推送里的 **触发条件** 会列出让这条提醒触发的条件。对 OR 来说，就是第一个命中的条件。

没有条件的 AND 组会被算作已满足。所以如果一条启用中的提醒最外层组还是空的，它会在每条变化上触发。

### 创建提醒 {#setting-up-alerts}

在你创建之前，提醒管理器会显示「没有找到提醒。从创建你的第一个探测信号开始」。从创建你的第一个探测信号开始」。

1. 点击 **打开提醒管理器**。
2. 点击 **新建提醒**。点击 **新建提醒**。列表里会立刻出现一条处于暂停状态、名为 **新提醒**、级别 **低**、带一个空 AND 组的提醒。
3. 把鼠标停在提醒上，点击 **编辑** 打开 **编辑提醒**。
4. 设置 **提醒名称** 和 **级别**（**低**、**中**、**高**）。
5. 在 **逻辑配置** 下设置 **匹配方式**。用 **条件** 添加条件（新条件默认是 **需求** EQ **值** 0），或用 **组** 添加嵌套的组。**移除** 会删掉一个条件或一个嵌套的组，但对最外层的组不起作用。没有条件的组会显示 **空组**。
6. 把 **状态** 从 **暂停** 改成 **启用**。
7. 点击 **保存**，或者用 **放弃** 丢掉你的改动。

> [!tip] 在把提醒设为 **启用** 之前，至少先加一个条件。启用中的提醒如果组是空的，会把每条变化都刷进推送。启用中的提醒如果组是空的，会把每条变化都刷进推送。

以后想改提醒，把鼠标停上去点击 **编辑**。**删除** 会立刻删掉它。列表显示每条提醒的名称以及它是 **启用** 还是 **暂停**，点 **关闭提醒管理器** 可以把列表收起来。
